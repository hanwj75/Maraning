# Character System

## Character Model

- 캐릭터 시스템은 학습 결과와 현재 상태를 짧고 귀엽게 전달하는 피드백 계층이다.
- 캐릭터는 진행의 중심이 아니라 보조 안내자 역할을 가진다.
- 캐릭터의 목표는 귀여운 UX 를 강화하되 학습 흐름을 방해하지 않는 것이다.

## Character States

### idle

- 기본 대기 상태다.
- `Home`, `DifficultySelect`, `StageMap` 에서 가볍게 존재감을 보여준다.

### encouraging

- Stage 시작 전이나 진행 가능 상태에서 사용자를 부드럽게 독려한다.
- 메시지와 동작은 짧아야 한다.

### success

- 정답 결과나 Stage 완료 후 긍정 반응을 보여준다.
- 성취감을 주되 다음 이동을 막지 않는다.

### mistake

- 오답이나 실패 상황에서 부정적 압박 없이 짧게 반응한다.
- 학습 지속 의지를 꺾지 않는 톤이어야 한다.

### reward

- `Reward` 화면에서 완료 결과와 함께 나타나는 상태다.
- 다음 Stage 나 StageMap 복귀를 자연스럽게 유도한다.

### low_jelly

- `jelly` 부족으로 Stage 시작이 막힌 상황을 설명한다.
- 좌절보다 안내 중심의 반응을 제공한다.

## Interaction Rules

- 캐릭터 반응은 항상 짧아야 한다.
- 캐릭터 반응은 사용자 입력을 오래 막지 않아야 한다.
- 긴 대사, 다단계 대화, 과한 감정 표현은 피한다.
- 피드백은 현재 상태 하나만 분명히 전달해야 한다.
- 같은 이벤트에 대한 반응은 일관된 톤을 유지해야 한다.

## Reward Integration

- `Reward` 화면에서는 `success` 또는 `reward` 상태를 사용한다.
- Stage 완료 피드백은 진행도 반영과 함께 자연스럽게 묶여야 한다.
- 광고 시청 후 `jelly` 회복이 발생하면 짧은 회복 반응을 보여줄 수 있다.
- 회복 반응은 보상 설명보다 빠르게 끝나야 한다.

## Flow Protection Rules

- 캐릭터는 `Home -> DifficultySelect -> StageMap -> Quiz -> Reward` 흐름을 지연시키지 않는다.
- 반응은 스킵 없이도 짧아야 하고, 필요 시 즉시 다음 화면 조작이 가능해야 한다.
- 학습 중 핵심 정보보다 캐릭터 연출이 먼저 오면 안 된다.
- 오답 상황에서도 캐릭터가 판정 결과를 모호하게 만들면 안 된다.

## Content Tone

- 문구는 짧고 단순한 영어 학습 분위기에 맞아야 한다.
- 톤은 귀엽고 가볍지만 유치하게 길어지지 않아야 한다.
- 실패 반응도 비난보다 재도전 유도에 집중한다.

## Open Questions

- 캐릭터를 단일 캐릭터로 고정할지, 스킨만 바꿀 수 있게 할지 여부.
- `low_jelly` 상태에서 광고 유도 문구를 캐릭터가 직접 말할지 여부.
